# Torrenta 1.4 — контракт доработки: один экземпляр, открытие торрентов из проводника, выход из приложения

Документ фиксирует **точные** имена, типы и семантику, которые одновременно
используют Tauri-бэкенд (`src-tauri`) и интерфейс (`src`). Ядро
(`crates/torrent-core`) в этой версии не меняется: доработка целиком лежит в
обвязке и интерфейсе.

## 1. Требования пользователя

1. Приложение не должно запускаться в нескольких экземплярах — только один
   процесс Torrenta.
2. Когда за Torrenta закреплено открытие `.torrent`-файлов, двойной щелчок по
   файлу должен открывать окно приложения и предлагать добавить торрент — так
   же, как при ручном добавлении файла, а не молча игнорировать запуск.
3. В сайдбаре, под пунктом «Настройки», нужна иконка «Выход», которая
   завершает приложение полностью — вместе с процессом, а не сворачивает окно
   в трей.

## 2. Один экземпляр приложения

Второй запуск `.exe` больше не создаёт вторую копию приложения: аргументы
запуска передаются уже работающему процессу, после чего второй процесс
завершается.

| Что | Значение |
| --- | --- |
| Крейт | `tauri-plugin-single-instance = "2"` (`2.5.5` на момент выпуска) |
| Место регистрации | `src-tauri/src/lib.rs::run`, **самый первый** `.plugin(...)` |
| Колбэк | `tauri_plugin_single_instance::init(\|app, argv, cwd\| ...)` |
| Есть источник в `argv` | `single_instance::queue_open(app, source)` — см. §3 |
| Источника нет | `tray::show_main(app)` — окно первого экземпляра показывается и получает фокус |

Плагин обязан регистрироваться первым: он проверяет наличие уже запущенного
процесса до инициализации остальных плагинов и окна.

## 3. Открытие `.torrent` и magnet из проводника

### 3.1 Разбор аргументов командной строки

```rust
// src-tauri/src/single_instance.rs
pub fn source_from_args(
    args: impl IntoIterator<Item = String>,
    base: Option<&std::path::Path>,
) -> Option<String>;
```

Функция берёт **первый подходящий** аргумент:

| Аргумент | Результат |
| --- | --- |
| `magnet:?xt=urn:btih:...` (префикс `magnet:` без учёта регистра) | возвращается как есть |
| `D:\Downloads\file.torrent` (оканчивается на `.torrent` без учёта регистра) | возвращается как есть |
| относительный `file.torrent` при `base = Some(dir)` и существующем файле | `dir.join(path)`, приведённый к строке через `Path::display()` |
| относительный `file.torrent` при отсутствии файла или `base = None` | строка без изменений — существование проверит предпросмотр в интерфейсе |
| `--flag`, `-x`, пустая строка, любой другой текст | игнорируется |

`args` — аргументы **без** имени исполняемого файла: при старте передаётся
`std::env::args().skip(1)`, в колбэке плагина — `argv` второго запуска (там
первым идёт путь к `.exe`, он не подходит под правила и просто пропускается).
Разбор не паникует на некорректном UTF-8: срезы строк идут только через
`str::get(..)`.

### 3.2 Хранение источника до готовности интерфейса

Окно создаётся `visible: false` и грузит фронтенд уже после `setup`, поэтому
источник складывается в состояние:

```rust
pub struct PendingOpen(std::sync::Mutex<Option<String>>);
```

* `Default` — пустое ожидание;
* `set(Option<String>)` — положить источник или очистить;
* `take() -> Option<String>` — забрать **один раз** (take-once), после чего
  ожидание пусто; блокировка берётся с `unwrap_or_else(|e| e.into_inner())`,
  то есть «отравленный» мьютекс не роняет приложение;
* `is_empty()` — для тестов и диагностики.

Состояние регистрируется в `setup` через `app.manage(PendingOpen::default())`
сразу после `AppEngine`, до любых вызовов `queue_open`.

### 3.3 Поднятие окна и сигнал интерфейсу

```rust
pub fn queue_open(app: &tauri::AppHandle, source: String);
```

Порядок действий: сохранить источник в `PendingOpen` → `tray::show_main(app)`
(показ, `unminimize`, фокус — даже если приложение запущено свёрнутым в трей) →
`app.emit(OPEN_EVENT, ())`.

```rust
pub const OPEN_EVENT: &str = "engine://open-source";
```

Событие **сигнальное**, полезной нагрузки нет: интерфейс по нему вызывает
команду `take_open_request` и открывает диалог добавления. Событие может
прийти, когда забирать уже нечего (источник забрали при инициализации или
вторым обработчиком) — повторный `take` вернёт `None`, это штатная ситуация.

### 3.4 Команды

```rust
#[tauri::command]
pub fn take_open_request(state: tauri::State<'_, PendingOpen>) -> Option<String>;
```

Забирает и очищает ожидающий источник. Вызывается дважды: при инициализации
интерфейса (первый запуск — событие ушло в пустоту, до подписки) и по событию
`engine://open-source`.

### 3.5 Путь запуска

| Сценарий | Что происходит |
| --- | --- |
| Torrenta не запущена, открыт `.torrent` | Windows стартует процесс с путём в `argv`; `setup` вызывает `queue_open`; интерфейс при инициализации забирает источник и открывает диалог добавления |
| Torrenta работает, открыт `.torrent` | Второй процесс передаёт `argv` первому через плагин, окно поднимается, интерфейс забирает источник по событию |
| Torrenta работает, запущен второй `.exe` без аргументов | Окно первого экземпляра просто показывается и получает фокус |

## 4. Полный выход из приложения

```rust
// src-tauri/src/commands.rs
#[tauri::command]
pub fn quit_app(app: AppHandle); // app.exit(0)
```

Завершает процесс целиком, игнорируя настройку «при закрытии окна сворачивать
в трей», — то же поведение, что у пункта «Выход» в меню значка трея. Отдельной
настройки у кнопки нет: подтверждения не запрашиваются, несохранённых данных в
приложении нет.

В интерфейсе команда доступна как `EngineApi.quitApp()`; в демо-режиме
(`mock`) это безопасный no-op — браузерная страница не может завершить процесс.

## 5. Интерфейс (`src`)

### 5.1 Кнопка «Выход» в сайдбаре

| Свойство | Значение |
| --- | --- |
| Место | футер сайдбара, третья кнопка: «Светлая/Тёмная тема» → «Настройки» → «Выход» |
| Классы | `side-action side-action--quit` (существующие стили + hover на токене `--color-danger`) |
| Иконка | `power`, 16 px (`src/lib/icons.ts`) |
| Подпись | «Выход» |
| Подсказка | «Выход (завершить приложение)» |
| Компактный режим (< 136 px) | подпись скрыта штатным правилом, кнопка 31×30 в центре, доступное имя — `aria-label="Выход"` |
| Действие | `options.onQuit()` → `api().quitApp()` |

Новых цветов не вводится: hover использует существующий токен
`--color-danger`, поэтому проверка контраста (`npm run check:contrast`)
остаётся прежней — 68 пар WCAG AA.

### 5.2 Приём внешнего источника

`EngineApi` получает три члена:

```ts
takeOpenRequest(): Promise<string | null>;
subscribeOpenRequest(listener: () => void): Promise<() => void>;
quitApp(): Promise<void>;
```

В Tauri-реализации: `invoke("take_open_request")`, `listen("engine://open-source")`
и `invoke("quit_app")`. В `app.ts`:

1. при инициализации сначала оформляется подписка на событие, затем
   **безусловно** вызывается `consumeOpenRequest()` — так забирается источник,
   переданный при первом запуске;
2. `consumeOpenRequest()` преобразует строку в `TorrentSource`
   (`magnet:?` → `{ kind: "magnet" }`, иначе `{ kind: "path" }`) и открывает
   **тот же** диалог добавления, что и ручное добавление (`openAdd`), — второго
   варианта формы в проекте нет;
3. ошибки показываются тостом «Не удалось открыть торрент», отписка от события
   снимается в `beforeunload` вместе с остальными подписками.

## 6. Ассоциация `.torrent` в установщике

В `src-tauri/tauri.conf.json` в раздел `bundle` добавлено:

```json
"fileAssociations": [
  {
    "ext": ["torrent"],
    "name": "BitTorrent",
    "description": "Torrent file",
    "mimeType": "application/x-bittorrent",
    "role": "Editor"
  }
]
```

Схема конфигурации Tauri 2 поле принимает (`role: Editor` — допустимое
значение `BundleTypeRole`; `rank` относится только к macOS и не задаётся).
Текст описания намеренно на латинице (`Torrent file`): WiX собирает `main.wxs`
с кодовой страницей 1252, и кириллица в `ProgId/@Description` валит сборку MSI
(`LGHT0311: A string was provided with characters that are not available in the
specified database code page '1252'`). Проверено сборкой: с русским описанием
NSIS собирался, а MSI — нет.
Фактическую запись ключей в реестр делает бандлер при сборке установщика:

* **NSIS** (`Torrenta_1.4.0_x64-setup.exe`, `installMode: currentUser`) —
  ассоциация пишется в `HKCU\Software\Classes`: расширение `.torrent`,
  ProgID с командой `"...\torrenta.exe" "%1"` (кавычки вокруг `%1` обязательны,
  иначе путь с пробелами ломается);
* **MSI/WiX** — объявляет ту же ассоциацию (`ProgId Torrenta.torrent` +
  `Extension torrent` + verb `open` с аргументом `"%1"`), но использует
  рекламируемые (`Advertise="yes"`) ключи, которые Windows создаёт при
  установке компонента; корректность на конкретной машине проверяется только
  установкой. Если после MSI `.torrent` не открывается в Torrenta, установите
  NSIS-версию или закрепите ассоциацию вручную через «Открыть с помощью →
  Выбрать другое приложение».

Пользователь, у которого ассоциация уже настроена вручную, ничего не теряет:
после установки 1.4.0 достаточно один раз выбрать Torrenta в «Открыть с
помощью».

## 7. Проверка

Автоматические гейты версии:

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run build
npm run check:contrast
```

Юнит-тестами покрыты (модуль `single_instance`): разбор magnet и `.torrent`
без учёта регистра, флаги перед путём, путь с пробелами и кириллицей,
относительный путь с `base` и без него, отсутствие подходящих аргументов,
take-once у `PendingOpen`, значение `OPEN_EVENT`.

Живьём на собранном приложении проверяется то, что не покрывается тестами:

1. запуск второго `torrenta.exe` не создаёт второе окно — первый поднимается
   и получает фокус, второй процесс исчезает из диспетчера задач;
2. двойной щелчок по `.torrent` при запущенном приложении открывает диалог
   добавления, при закрытом — запускает приложение и сразу открывает диалог;
3. путь с пробелами и кириллицей в имени файла передаётся без искажений;
4. кнопка «Выход» в сайдбаре завершает процесс, даже когда включено
   «при закрытии окна сворачивать в трей»;
5. после установки из NSIS `.torrent` открывается в Torrenta (см. §6).
