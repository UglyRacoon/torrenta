# Torrenta 1.5 — контракт доработки: сессия, уведомления, подсказка в трее, папка наблюдения

Документ фиксирует, что именно вошло в версию 1.5: зачем это нужно, как устроено
и какие ограничения остались. Код, названия файлов и чисел можно проверять
прямо по нему — все формулировки сверены с реализацией.

## 1. Требования пользователя

После 1.4 оставались четыре бытовые проблемы, из-за которых клиент неудобно
держать запущенным постоянно:

1. **Список торрентов терялся при перезапуске** — постоянными были только
   настройки. После выхода и запуска всё приходилось добавлять заново.
2. **О завершении загрузки не сообщалось** — когда окно свёрнуто в трей или
   скрыто за другими программами, момент завершения приходилось ловить глазами.
3. **Иконка в трее ничего не показывала** — по ней нельзя было понять, качает
   ли клиент что-то сейчас, не открывая окно.
4. **Не было папки наблюдения** — `.torrent`-файл нужно было каждый раз
   выбирать вручную, хотя браузеры и менеджеры загрузок умеют складывать их в
   один каталог.

Версия 1.5 закрывает все четыре пункта и не меняет протокольную часть: ядро
`torrent-core` в этой версии не правилось вообще.

## 2. Сохранение и восстановление сессии

### 2.1 Где лежит сессия

```
<каталог конфигурации приложения>\session\
├── session.json                          список торрентов
└── session-data\
    └── <info_hash>.torrent               копии метаданных файловых торрентов
```

Каталог конфигурации — тот же, где лежит `settings.json` (см. `docs/BUILD.md`,
раздел о путях). Сессия — отдельный модуль `src-tauri/src/session.rs`; копии
`.torrent` хранятся отдельными файлами, а не строкой в JSON: так `session.json`
остаётся читаемым глазами, а метаданные не раздуваются в base64.

Запись `session.json`:

```json
[
  {
    "info_hash": "0123456789abcdef0123456789abcdef01234567",
    "name": "Пример",
    "source": { "kind": "file", "file": "0123456789abcdef0123456789abcdef01234567.torrent" },
    "save_path": "D:\\Downloads",
    "paused": false,
    "selected_files": [0, 2],
    "priorities": [{ "index": 1, "priority": "low" }],
    "down_limit_kib": 0,
    "up_limit_kib": 0
  }
]
```

Правила формата:

- `source` — либо `{"kind":"file","file":"<hash>.torrent"}`, либо
  `{"kind":"magnet","link":"magnet:?..."}`; по нему выбирается способ
  восстановления;
- `selected_files` пустой массив означает «выбраны все файлы» — так запись
  остаётся компактной, а тип выбора однозначным;
- `priorities` содержит только отличия от обычного приоритета;
- `paused` — только ручная пауза; торрент в очереди («В очереди») не считается
  приостановленным и после восстановления встаёт в очередь заново;
- отсутствующие в JSON поля заполняются значениями по умолчанию, поэтому файл,
  записанный более старой версией, читается без ошибок.

Имя файла копии при чтении **вычисляется из `info_hash`**, а не берётся из
строки `source.file`: подменённый в JSON путь не даст выйти за пределы
`session-data`. Хеш перед использованием проверяется — в нём должны быть
ровно 40 шестнадцатеричных символов.

### 2.2 Когда сессия сохраняется

Сохранением занимается тот же тикер состояния, что рассылает `engine://state`:

- не чаще одного раза в **2 секунды** (`SESSION_SAVE_INTERVAL`);
- только если изменилась **полезная нагрузка** — сериализованный список записей
  без прогресса. Скорость, ETA и число скачанных байт в сессию не попадают,
  поэтому во время загрузки диск не дёргается каждые полсекунды;
- запись атомарна: данные пишутся во временный файл, сбрасываются на диск
  (`sync_all`) и переименовываются в `session.json`; при ошибке временный файл
  удаляется;
- при выключенной настройке «Восстанавливать сессию при запуске» запись не
  идёт вообще, а запомненный хеш сбрасывается — после включения настройки файл
  обновится сразу.

Удаление торрента из списка удаляет и его запись, и копию `.torrent` в
`session-data` (если файла уже нет — это не ошибка).

Источник торрента запоминается в момент добавления: команда `add_torrent`
после успешного `add_file_with`/`add_magnet_with` кладёт в реестр сессии
исходные байты `.torrent` или magnet-ссылку. Ошибка регистрации не ломает
добавление — торрент просто не переживёт перезапуск, а причина уходит в журнал.
Торренты, добавленные через папку наблюдения, регистрируются там же.

### 2.3 Как проходит восстановление

1. После показа окна запускается фоновая задача `spawn_session_restore`.
2. Настройка `restore_session` читается один раз: если она выключена, задача
   сразу завершается.
3. `session.json` читается целиком; битый JSON — одна запись в журнал и пустой
   список восстановления, паники нет.
4. Для каждой записи: файловая — `add_file_with(bytes, AddOptions { save_path, files })`,
   magnet — `add_magnet_with(link, AddOptions { save_path, files })`.
5. Затем к добавленному торренту применяются `paused`, лимиты скорости и
   приоритеты файлов (приоритеты — только когда движок уже знает число файлов).
6. Ошибка на одной записи (нет копии `.torrent`, файл повреждён, торрент уже
   добавлен) не мешает остальным: запись пропускается, в журнал уходит строка
   с причиной, счётчики `restored`/`skipped` печатаются одним итогом.

Восстановление идёт в фоне и не задерживает старт: окно показывается сразу,
торренты появляются в списке по мере готовности. Повторной проверки файлов при
старте нет — прогресс движок считает по своим данным, а «Перепроверить файлы»
остаётся ручным действием.

### 2.4 Ограничения восстановления

- **Magnet восстанавливается по ссылке**: метаданные при следующем запуске
  качаются у пиров заново, поэтому до их получения имя и размер не известны.
  Выбор файлов применяется после получения метаданных; приоритеты `Низкий` и
  `Высокий` у magnet-торрентов не восстанавливаются и возвращаются к обычному.
- Если записанный `save_path` больше не существует или не абсолютный,
  используется каталог загрузки по умолчанию — торрент не теряется, причина
  пишется в журнал.
- `session.json` доступен пользователю: испорченные записи пропускаются, но
  остальные восстанавливаются.
- Настройка «Восстанавливать сессию» выключает и запись, и чтение: файл от
  прошлой настройки не используется, пока настройку не включат снова.

## 3. Уведомления Windows

К событию движка `Completed` (торрент завершён) приложение показывает системное
уведомление: заголовок «Torrenta», текст ««Имя» загружен».

Условия показа:

- включена настройка `notify_on_complete` (по умолчанию включена);
- главное окно **не видимо или не в фокусе** — если пользователь и так смотрит
  на список, уведомление не нужно; ошибки Tauri при проверке трактуются как
  «не в фокусе» (лучше показать лишнее, чем пропустить завершение).

Уведомления реализованы плагином `tauri-plugin-notification` и вызываются из
Rust, а не из интерфейса. Поэтому в окне нужно разрешение
`notification:default` (файл `src-tauri/capabilities/default.json`), а фронтенду
доступ к плагину не требуется. Ошибка показа (выключенные уведомления в
Windows, запрет в параметрах системы) только логируется и не влияет на загрузки.

Уведомление показывается один раз на завершение: событие `Completed` движок
отдаёт единожды, повторно оно не генерируется ни при перезапуске, ни при
перепроверке.

## 4. Подсказка значка в трее

Подсказка (tooltip) обновляется из того же тикера, что и статистика, не чаще
раза в 2 секунды, а также принудительно при смене текста — иконку могут
пересоздать, и подсказка потерялась бы.

Формат:

| Состояние | Текст |
| --- | --- |
| Есть активные торренты | `Torrenta — ↓ 4,2 МБ/с · ↑ 512 КБ/с · 3 из 5` |
| Все на паузе / список пуст | `Torrenta — нет активных загрузок` |

Числа выводятся теми же функциями форматирования, что и в интерфейсе
(русская запятая в дробях, «КБ/с», «МБ/с», «ГБ/с»), поэтому подсказка и
статусбар не расходятся. Длина текста обрезается до 120 символов по символам,
а не по байтам — кириллица не рвётся посередине.

## 5. Папка наблюдения

### 5.1 Настройка

Новое поле `watch_dir` в `settings.json` (пустая строка — наблюдение
выключено). При сохранении настроек строка обрезается по краям; если она
непустая, приложение требует **абсолютный путь** и создаёт каталог при
необходимости. Относительный путь или файл вместо каталога дают русскую ошибку
в диалоге настроек — молча «починить» путь нельзя, иначе файлы поедут не туда.

В окне настроек поле доступно только для чтения, рядом две кнопки: «Выбрать…»
(системный диалог выбора папки, заголовок «Папка наблюдения») и «Очистить»
(выключает наблюдение). Папка применяется без перезапуска: задача читает
настройку на каждом тике.

### 5.2 Опрос папки

Раз в **3 секунды** (`WATCH_INTERVAL`) задача просматривает каталог:

- интересуют только файлы с расширением `.torrent` (регистр не важен);
- файл должен быть **обычным** (не каталог и не ссылка) и **непустым**;
- файл не должен меняться последние **2 секунды** (`WATCH_MIN_AGE`) — так
  недописанный браузером `.torrent` не читается наполовину;
- обход идёт по именам (сначала по нижнему регистру, затем по точному пути),
  поэтому порядок добавления предсказуем и одинаков между запусками.

Файлы добавляются в папку загрузки из настроек, с выбором всех файлов и без
лимитов. Торрент сразу регистрируется в сессии и переживает перезапуск.

### 5.3 Что происходит с файлом

- успешно добавленный файл переезжает в `<watch_dir>\done\`;
- файл, который добавить не удалось (пустой, повреждённый, уже добавленный),
  тоже переезжает в `done` — иначе ошибка повторялась бы каждый тик, пока файл
  лежит на месте; причина печатается в журнал;
- имена в `done` не перезаписываются: при совпадении добавляется суффикс
  ` (2)`, ` (3)` и так далее;
- перенос — `rename`, а при переходе между дисками (или занятом файле) —
  копирование с удалением;
- одинаковые сообщения журнала не повторяются каждый тик: печатается только
  изменившийся текст (`LoudOnce`), поэтому недоступная папка не заливает stderr.

## 6. Настройки версии 1.5

К прежним полям `settings.json` добавлены три:

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `notify_on_complete` | bool | `true` | показывать уведомление Windows о завершении загрузки |
| `watch_dir` | строка | `""` | папка наблюдения; пусто — выключено |
| `restore_session` | bool | `true` | восстанавливать список торрентов при запуске |

Старый `settings.json` без этих полей читается без ошибок: недостающие
значения берутся по умолчанию. Обратная запись симметрична — `get_settings`
всегда отдаёт все три поля, поэтому интерфейс может не проверять `undefined`.

## 7. Интерфейс (`src`)

- В модальном окне настроек появился блок «Папка наблюдения» с полем только для
  чтения и кнопками «Выбрать…»/«Очистить», а в блоке «Поведение» — переключатели
  «Показывать уведомление о завершении» и «Восстанавливать список торрентов при
  запуске».
- Новая команда `pick_watch_dir` возвращает выбранный путь или `null`, если
  пользователь закрыл диалог.
- Мок-режим (`npm run dev` без Tauri) поддерживает новые поля и команду, поэтому
  интерфейс можно отлаживать в браузере без сборки Rust.
- Поле с путём — `readonly`: правка руками не предусмотрена, поэтому путь
  всегда абсолютный и проверенный.

## 8. Команды и разрешения

- Всего команд стало **25**: добавлена `pick_watch_dir`.
- В `src-tauri/capabilities/default.json` добавлено разрешение
  `notification:default` — оно нужно плагину уведомлений. Пользовательские
  команды Rust по-прежнему не требуют ACL-записей.
- Новые зависимости: `tauri-plugin-notification = "2"` (Rust). Фронтенд-пакеты
  не менялись.

## 9. Проверка

Версия считается готовой, когда зелёные все проверки:

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run build
npm run check:contrast
```

Тестов в наборе стало **254**: 141 в ядре `torrent-core` (без изменений) и 113
в обвязке `torrenta_lib` — плюс 37 новых:

| Что проверяется | Тестов |
| --- | --- |
| Сессия: формат, roundtrip всех полей, частичный и битый JSON, атомарная запись, отсутствие временных файлов, копии `.torrent`, защита от подмены пути, пропуск только битых записей, сборка записей из снимка, сортировка, `payload_hash`, `forget` | 21 |
| Папка наблюдения: фильтр расширения и возраста, обычный непустой файл, сортировка, уникальные имена в `done`, перенос, дедупликация журнала | 8 |
| Подсказка трея: формат со скоростями, текст без активных загрузок, обрезка по символам, форматирование скоростей | 5 |
| Настройки: значения по умолчанию, нормализация, чтение старого `settings.json`, snake_case и roundtrip, проверка папки наблюдения | 4 |

Дополнительно проверено вручную на собранном приложении:

1. добавление торрента → выход → запуск: торрент на месте, папка, пауза и
   выбранные файлы совпадают;
2. завершение загрузки при свёрнутом в трей окне → уведомление Windows;
3. подсказка трея показывает скорости и число активных торрентов;
4. `.torrent`, положенный в папку наблюдения, добавляется в течение нескольких
   секунд и переезжает в `done`;
5. настройки: выбор и очистка папки наблюдения, переключатели уведомлений и
   восстановления сохраняются и применяются без перезапуска.

## 10. Что осталось за рамками версии

- Сессия хранит **список и параметры**, но не прогресс: прогресс по-прежнему
  восстанавливается по данным на диске (при необходимости — вручную через
  «Перепроверить файлы»).
- Папка наблюдения не удаляет скачанные данные и не следит за подкаталогами:
  обход только по верхнему уровню.
- Уведомления не настраиваются по типам (только «завершено»), звук и стиль
  определяет Windows.
- Настройка прокси, DHT, PEX и web-seed остаются на следующие версии — контракт
  1.6 описан отдельно.
