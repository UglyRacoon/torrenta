# Torrenta 1.3 — контракт доработки: папка торрента, свободные файлы, перепроверка, очередь

Документ фиксирует **точные** имена, типы и семантику, которые одновременно
используют ядро (`crates/torrent-core`), Tauri-бэкенд (`src-tauri`) и интерфейс
(`src`). Менять контракт можно только по согласованию с Lead: любое расхождение
ломает сборку у соседа.

## 1. Требования пользователя

1. Пункт «Открыть папку загрузок» в контекстном меню должен открывать папку
   **этого** торрента — ту же, что кнопка «Каталог» в подробностях, а не общий
   каталог загрузки из настроек.
2. Скачанный `.exe`, пока торрент раздаётся, Windows не даёт запустить: «файл
   занят другой программой». Другие клиенты позволяют открывать файлы при
   активной раздаче.
3. В контекстном меню нужна перепроверка файлов торрента.
4. Когда в выбранном фильтре пусто, сообщение «Ничего не найдено» и кнопка
   «Сбросить фильтры» должны стоять по центру области списка, а не у нижней
   кромки окна.
5. Нужны приоритеты файлов внутри торрента и ограничение числа одновременно
   активных раздач — отдельно на скачивание и на раздачу.

## 2. Ядро (`crates/torrent-core`)

### 2.1 Приоритеты файлов

```rust
// engine::FilePriority, реэкспорт torrent_core::FilePriority
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum FilePriority {
    Skip,
    Low,
    #[default]
    Normal,
    High,
}
```

`FileView` (то, что уходит в интерфейс) получает поле `priority`:

```rust
pub struct FileView {
    pub path: String,
    pub length: u64,
    pub downloaded: u64,
    pub selected: bool,
    pub priority: FilePriority,
}
```

Перевод приоритетов в уровни кусков (`selection::piece_levels`):

| Приоритет | Файл скачивается | Уровень кусков |
| --- | --- | --- |
| `High` | да | 2 |
| `Normal` | да | 1 |
| `Low` | да | 0 |
| `Skip` | нет | 0 (кусок не нужен) |

Правила:

* уровень куска — **максимум** по всем файлам, которые в него попали: общий
  кусок двух файлов получает приоритет более важного;
* `PiecePicker` перебирает уровни от 2 к 0, то есть сначала отдаются куски
  высокого приоритета, затем обычного, затем низкого; внутри уровня работает
  прежний rarest-first;
* `Skip` — то же, что снятая галочка: кусок не запрашивается, файл помечен
  `selected = false`; уже скачанное остаётся на диске;
* API: `TorrentManager::set_file_priorities(&self, id: u64, priorities: Vec<FilePriority>) -> Result<(), EngineError>`;
  вектор — полный список приоритетов в порядке файлов торрента. Неверная длина
  возвращает `EngineError::Selection`, неизвестный id — `NotFound(id)`;
* до получения метаданных (magnet) приоритеты складываются в
  `pending_priorities` и применяются в `install()`; явный список файлов
  (`set_file_selection`) и приоритеты взаимоисключающи — каждый вызов очищает
  ожидающий результат другого;
* `get_state` отдаёт приоритет в `files[].priority`, поэтому интерфейс не
  хранит его отдельно.

### 2.2 Очередь и лимиты активности

```rust
#[serde(default)]
pub struct EngineConfig {
    pub max_active_downloads: usize, // 0 — без ограничения
    pub max_active_seeds: usize,     // 0 — без ограничения
}
```

* в `sanitized()` оба значения ограничиваются `MAX_ACTIVE_LIMIT = 500`; бэкенд
  ужимает их до 100, поэтому в интерфейсе диапазон 0..100;
* `TorrentState` получает вариант `Queued` (`"queued"`), а порядок вариантов
  теперь `Queued, Metadata, Checking, Downloading, Seeding, Paused, Completed,
  Error`;
* планировщик (`plan`/`schedule`) считает активные загрузки и активные раздачи
  отдельно, пропускает торренты на ручной паузе, в проверке и в ошибке, и
  активирует не больше лимита. Слоты отдаются по порядку добавления
  (`added_at`, затем `id`), а не по алфавиту или прогрессу;
* `activate` снимает паузу, ставит состояние (`Downloading`/`Metadata`/
  `Seeding`), забирает файлы на запись и возвращает пиров в очередь;
* `park` ставит паузу, **отпускает файлы на запись**, ставит `Queued`;
* освободившийся слот (`завершение`, `пауза`, `удаление`) запускает следующего
  в очереди; `pause_all`/`resume_all` работают как раньше, но после
  `resume_all` лишние торренты уходят в очередь;
* ручная пауза сильнее очереди: такой торрент слот не занимает и сам не
  запускается.

### 2.3 Перепроверка файлов

```rust
pub fn recheck(&self, id: u64) -> Result<(), EngineError>
```

* состояние сразу меняется на `Checking`, `pieces_have` обнуляется, обмен с
  пирами останавливается, файлы на запись отпускаются;
* каждый кусок читается с диска и сверяется по SHA-1 с `pieces` из метаданных;
  прогресс проверки виден как `pieces_have` от 0 до `piece_count`,
  `eta_seconds = 0`;
* после проверки восстанавливается битовая карта и `have_bytes` — по факту на
  диске, а не по прошлой сессии; итоговое состояние: `Seeding` (полностью и
  раздача включена), `Completed` (полностью, раздача выключена), `Downloading`
  (данных не хватает) или `Paused` (торрент был на ручной паузе);
* повторный вызов во время проверки — идемпотентный `Ok(())`;
* `NotReady` — торрент ещё без метаданных, `NotFound(id)` — неизвестный id;
* проверка не переподключает пиров: после неё торрент продолжает работу с уже
  известными адресами.

### 2.4 Файлы, которые можно открывать

Причина ошибки «файл занят другой программой»: Windows-загрузчик открывает
`.exe` с `FILE_SHARE_READ | FILE_SHARE_DELETE`, поэтому дескриптор на запись у
другого процесса даёт `ERROR_SHARING_VIOLATION`. Что сделано в `Storage`:

* все файлы открываются с `share_mode = FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`
  (`TORRENT_SHARE_MODE`), поэтому клиент не мешает другим процессам;
* на запись файлы держатся только пока торрент реально качает;
* при завершении загрузки, паузе, постановке в очередь и перепроверке вызывается
  `release_writes()`: данные `flush` + `sync_data`, файлы переоткрываются
  **только для чтения**; `acquire_writes()` возвращает запись перед продолжением;
* в освобождённом состоянии `write_at` возвращает `PermissionDenied` —
  случайная запись в «занятые» файлы невозможна;
* `release_writes`/`acquire_writes` идемпотентны, состояние видно по
  `writes_released()`.

## 3. Бэкенд (`src-tauri`)

### 3.1 Настройки — два новых поля

`SettingsDto` (`src-tauri/src/settings.rs`, `settings.json`, всё в `snake_case`):

```rust
pub max_active_downloads: u32, // «Одновременно скачивать»
pub max_active_seeds: u32,     // «Одновременно раздавать»
```

* по умолчанию `0` — без ограничения; структура помечена `#[serde(default)]`,
  поэтому `settings.json` от 1.0–1.2 без этих ключей читается и даёт `0`;
* `MAX_ACTIVE_LIMIT = 100`, `clamp_active(value) -> u32` применяется в
  `normalize()`, при чтении файла и в ошибке валидации; `0` остаётся нулём;
* значения уходят в `EngineConfig` через `to_engine_config()` и возвращаются
  через `from_engine_config()`; движок дополнительно ограничивает их до 500.

### 3.2 Новые команды

```rust
pub fn recheck_torrent(id: u64) -> Result<(), String>;
pub fn set_file_priorities(id: u64, priorities: Vec<FilePriorityDto>) -> Result<(), String>;
```

`FilePriorityDto` — `"skip" | "low" | "normal" | "high"` с `From`-преобразованием
в `torrent_core::engine::FilePriority`. Ошибки движка превращаются в русский
текст в `state::engine_error_text`, поэтому интерфейс показывает их без
перевода. В `invoke_handler!` теперь 22 команды (было 20).

### 3.3 Состояние и отпечатки

* `state_code`: `Checking => 7`, `Queued => 0`, остальные коды не менялись;
* `priority_code`: `Skip=0, Low=1, Normal=2, High=3` — приоритет входит в
  «значимый» хеш состояния, поэтому смена приоритета сразу доезжает до
  интерфейса, а тикающие скорости остаются в «динамической» части.

### 3.4 «Открыть папку торрента»

`reveal_torrent` открывает в Проводнике папку именно этого торрента
(`save_path` торрента, а не общий `download_dir` из настроек): у многофайлового
торрента — его корневую папку, у однофайлового — папку загрузки с выделенным
файлом. Если файлов ещё нет, но папка существует, открывается папка; если нет и
её, команда возвращает ошибку «файлы торрента ещё не загружены: «…»». Та же
команда стоит за кнопкой «Каталог» в подробностях, поэтому оба пути ведут в
одно место.

## 4. Интерфейс (`src`)

### 4.1 Контекстное меню

* «Перепроверить файлы» (иконка `refresh`), во время проверки пункт disabled;
* «Открыть папку торрента» (иконка `folderOpen`) вместо «Открыть папку
  загрузок» — вызывает `reveal_torrent`;
* пункт паузы (во время проверки он подписан «Пауза») тоже disabled: движок
  не принимает паузу, пока идёт проверка.

### 4.2 Файлы: приоритеты

* в строке файла селект «Высокий / Обычный / Низкий / Не скачивать» заменил
  прежнюю галочку выбора: «Не скачивать» — это `Skip`, то есть та же снятая
  галочка. Любой выбор отправляет полный список приоритетов
  (`set_file_priorities`) и при ошибке откатывается к последнему снимку движка;
* кнопки «Выбрать все» и «Снять все» ставят всем файлам `Normal` и `Skip`;
* в строке файла поля не перерисовываются при каждом тике: обновление идёт
  только если приоритет из снимка разошёлся с текущим;
* смена приоритета у выбранного файла не сбрасывает выделение и не трогает
  загрузку — движок применяет её на следующем запросе куска;
* сводка под списком «Скачивается N из M · объём» считает файлы без `Skip`.

### 4.3 Пустое состояние

Область списка — сетка; сообщение и кнопка «Сбросить фильтры» стоят по центру
по вертикали и горизонтали с отступом от верха, а не прижаты к низу окна.
Текст зависит от причины: пустой фильтр, пустой поиск, нет загрузок вообще,
ничего не совпало с запросом. Кнопка сбрасывает и фильтр, и поисковый запрос.

### 4.4 Настройки: очередь

Группа «Очередь и активность»: поля «Одновременно скачивать» и «Одновременно
раздавать», числовые 0..100, подсказка «0 — без ограничения.». Ошибка ввода
показывается под полями (`.form-error`), сохранение не применяет невалидные
значения.

### 4.5 Состояние «Проверка»

`checking` — отдельное состояние: подпись «Проверка», прогресс в строке
«проверка данных · N %», бейдж `checking`. В список действий торрента оно не
входит (`actionFor("checking") => null`), а в статусбаре не считается активной
загрузкой.

## 5. Проверка

Автоматические тесты: `cargo test --workspace` — 206 тестов, из них 137 в ядре
(появились `crates/torrent-core/tests/scheduling.rs`: очередь, лимиты раздачи,
перепроверка, приоритеты файлов, освобождение файловых дескрипторов на Windows)
и 69 в Tauri-обвязке (новые поля настроек, валидация, roundtrip).

| Проверка | Результат |
| --- | --- |
| `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` | чисто, без предупреждений |
| `cargo test --workspace` | 206 тестов зелёные |
| `npm run build` (типы + Vite) | собирается, бандл в бюджете |
| `npm run check:contrast` | AA во всех парах палитры |
| Лимит одновременных загрузок | лишние торренты встают в `Queued` и запускаются по одному после освобождения слота |
| Лимит одновременных раздач | считается отдельно от загрузок |
| Ручная пауза при лимите | не занимает слот и не запускается сама |
| Перепроверка на диске | состояние `Checking` → прогресс по кускам → `Seeding`/`Completed` |
| Перепроверка после порчи данных | битые куски помечаются отсутствующими и докачиваются |
| Приоритеты файлов | `High` запрашивается раньше `Low`, `Skip` исключает куски, общий кусок берёт максимум |
| Запуск скачанного `.exe` при раздаче | файлы открыты только для чтения, ошибка «файл занят» не появляется |
| «Открыть папку торрента» и «Каталог» | открывают одну и ту же папку торрента |
| Пустое состояние | сообщение и кнопка по центру области списка |

Ограничения этого выпуска:

* перепроверка не ищет новых пиров: пока она идёт, обмен остановлен, а после
  неё торрент работает с уже известными адресами;
* состояние «Проверка» не попадает в фильтр «Загрузки» и не занимает слот
  ограничения одновременных загрузок — оно видно в «Все»;
* на паузе и в очереди файлы только для чтения: запуск скачанного работает, а
  запись в эти файлы другими программами — нет; при активной загрузке файл
  открыт на запись;
* очередь работает по порядку добавления и не ротируется по времени: если
  активный торрент «висит» без пиров, слот не переходит к следующему сам;
* если всем файлам поставить «Не скачивать», нужных кусков не остаётся и торрент
  сразу считается завершённым (`Seeding` при включённой раздаче, иначе
  `Completed`) — кнопка «Перепроверить файлы» после этого по-прежнему проверяет
  данные на диске;
* `left` в announce, как и раньше, считается по выбранным файлам.
