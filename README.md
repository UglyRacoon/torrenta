# Torrenta

**Лёгкий торрент-клиент для Windows на Rust и Tauri.** Собственное ядро протокола BitTorrent, компактный интерфейс в одном окне и нативный `.exe` с установщиком — без Electron и без сторонних торрент-движков.

## О проекте

Torrenta — настольное приложение для Windows 10/11 x64, написанное целиком на Rust (бэкенд и торрент-движок) и TypeScript (интерфейс в WebView2). Движок живёт в отдельном крейте `torrent-core`, не зависит от Tauri и тестируется как обычная библиотека: разбор `.torrent` и magnet-ссылок, работа с HTTP(S)- и UDP-трекерами, peer wire protocol, хранилище кусков и планировщик загрузки.

В проекте нет готовых торрент-библиотек: bencode, метаданные, трекеры, обмен кусками и проверка SHA-1 реализованы в этом репозитории.

**Что не нужно:** Electron, внешний демон, аккаунт, телеметрия. Приложение работает локально и ничего никуда не отправляет, кроме announce-запросов на трекеры вашего торрента.

## Возможности

- **Добавление торрентов:** файл `.torrent`, magnet-ссылка, перетаскивание `.torrent` в окно, диалог выбора файлов.
- **Magnet-ссылки:** получение метаданных у пиров по `ut_metadata` (BEP 9) без предварительного скачивания `.torrent`.
- **Трекеры:** HTTP(S)-announce и UDP-announce (BEP 15), компактные списки пиров (BEP 23).
- **Входящие подключения:** собственный TCP-приём на выбранном порту, не только исходящие соединения к пирам.
- **Прогресс в реальном времени:** снимок состояния на каждые 500 мс — скорость загрузки и отдачи, число подключённых и известных пиров, ETA, доля готовых кусков.
- **Раздача:** после завершения торрент продолжает отдавать куски (поведение настраивается).
- **Управление:** пауза и продолжение для одного торрента или для всех сразу, удаление с диска или только из списка.
- **Настройки:** каталог загрузки, лимиты скорости (КиБ/с), порт прослушивания, максимум пиров на торрент, раздача после завершения, тема оформления — сохраняются в `settings.json` в каталоге конфигурации приложения.
- **Интеграция с системой:** открытие папки загрузки и файла торрента в Проводнике, открытие внешних ссылок в браузере по умолчанию.
- **Собственное ядро:** один крейт без внешних торрент-зависимостей, покрытый юнит-тестами; тесты запускаются командой `cargo test --workspace`.

## Интерфейс

Одно окно в тёмной теме (есть светлая), четыре области:

| Область | Содержимое |
| --- | --- |
| Слева (сайдбар) | Фильтры по состоянию: все, загружаются, раздаются, завершённые, на паузе, ошибки |
| Сверху (панель) | Добавление magnet-ссылки или файла `.torrent`, поиск по списку |
| В центре (список) | Строки торрентов: имя, прогресс, скорость загрузки и отдачи, число пиров, состояние |
| Справа (детали) | Метаданные выбранного торрента, список файлов, трекеры, подключённые пиры |
| Внизу (статусбар) | Суммарная скорость загрузки и отдачи, число активных торрентов |

Дополнительно: всплывающие уведомления (toasts), модальные окна настроек и добавления торрента, оверлей перетаскивания файлов.

Палитра задана в [src/styles/tokens.css](src/styles/tokens.css) и проверяется скриптом `npm run check:contrast`: контраст текста к фону не ниже требований WCAG AA.

## Архитектура

Три слоя, каждый в своей части репозитория:

```
src/  ──invoke──▶  src-tauri/  ──прямые вызовы──▶  crates/torrent-core/
(WebView2 + TS)    (Tauri-команды, настройки,       (движок: метаданные,
                    состояние, события)              трекеры, пиры, куски, диск)
```

- **`crates/torrent-core`** — движок без Tauri. Модули: `bencode`, `metainfo`, `magnet`, `tracker`, `wire`, `bitfield`, `picker`, `storage`, `peerid`, `engine` (`TorrentManager`, `Runtime` одного торрента, сессия с пиром).
- **`src-tauri`** — тонкая обвязка: команды `get_state`, `add_torrent_file`, `add_torrent_bytes`, `add_magnet`, `pick_torrent_files`, `pick_download_dir`, `pause_torrent`, `resume_torrent`, `pause_all`, `resume_all`, `remove_torrent`, `get_settings`, `set_settings`, `reveal_torrent`, `open_download_dir`, `open_external`. Состояние уходит в интерфейс событием `engine://state`, события движка — `engine://event`.
- **`src`** — интерфейс на TypeScript без фреймворка: тонкий слой событий и отрисовка DOM. Тема применяется до первой отрисовки, чтобы не было мигания.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (слои, потоки данных, tokio-задачи, принятые решения) и [docs/CORE_API.md](docs/CORE_API.md) (публичный API ядра).

## Требования

- **ОС:** Windows 10 или Windows 11, x64.
- **WebView2 Runtime** — в Windows 11 уже установлен; в Windows 10 может потребоваться установка (установщик Torrenta умеет доставлять его сам).
- **Visual Studio Build Tools 2022** с нагрузкой «Разработка классических приложений на C++» (MSVC, Windows SDK) — нужны для компиляции Rust под MSVC.
- **Rust:** стабильный тулчейн 1.77 или новее, `stable-x86_64-pc-windows-msvc`.
- **Node.js:** 20 или новее вместе с npm (для сборки интерфейса).

Скрипт `build-windows.ps1` проверяет всё перечисленное и при необходимости сам ставит Rust и Node.js через `winget`.

## Быстрый старт

```powershell
npm install
npm run tauri dev
```

`npm run tauri dev` собирает Rust-часть в режиме отладки, поднимает Vite и открывает окно приложения с горячей перезагрузкой интерфейса.

Полезные команды интерфейса:

```powershell
npm run dev             # только Vite, без окна Tauri
npm run build           # tsc --noEmit + vite build
npm run check:contrast  # проверка контрастности палитры
```

## Сборка

Релизная сборка одной командой (Windows PowerShell 5.1 и PowerShell 7):

```powershell
.\build-windows.bat
```

или напрямую скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-windows.ps1
```

Скрипт проверяет окружение (Windows x64, MSVC, WebView2, Rust с MSVC-тулчейном, Node.js 20+), при необходимости устанавливает Rust и Node.js, выполняет `npm ci`, `npm run check:contrast`, `npm run build`, `cargo test --workspace` и `npm run tauri build`, после чего печатает пути, размеры и время сборки.

Параметры:

| Параметр | Действие |
| --- | --- |
| `-SkipTests` | не запускать `cargo test` |
| `-NoInstall` | ничего не устанавливать, только проверить окружение и зависимости |
| `-Dev` | запустить `npm run tauri dev` вместо релизной сборки |
| `-Clean` | `cargo clean`, удаление `node_modules` и `dist` перед сборкой |
| `-BundleOnly` | только установщик NSIS: `npm run tauri build -- --bundles nsis` |
| `-Help` | краткая справка по параметрам |

Результаты сборки:

| Артефакт | Путь |
| --- | --- |
| Исполняемый файл | `target\release\torrenta.exe` |
| Установщик NSIS | `target\release\bundle\nsis\Torrenta_1.0.0_x64-setup.exe` |
| Установщик MSI | `target\release\bundle\msi\Torrenta_1.0.0_x64_*.msi` |

Ручная сборка без скрипта:

```powershell
npm ci
npm run build
cargo test --workspace
npm run tauri build
```

Подробная инструкция по зависимостям и типичным ошибкам (WebView2, MSVC, длинные пути, антивирус, «link.exe not found») — в [docs/BUILD.md](docs/BUILD.md).

## Тесты

```powershell
cargo test --workspace     # юнит-тесты ядра и обвязки
npm run check:contrast     # контрастность цветовой палитры интерфейса
npm run build              # проверка типов TypeScript + сборка фронтенда
```

Тесты ядра не требуют сети: трекеры, пиры и хранилище проверяются на локальных заглушках.

Сейчас в наборе 125 тестов: 83 юнит-теста ядра, 14 интеграционных (рой пиров, устойчивость к сбоям, magnet-метаданные, регрессии) и 28 тестов Tauri-обвязки; полный прогон занимает около 40 секунд.

## Поддерживаемые BEP

| BEP | Что реализовано |
| --- | --- |
| 3 | Базовый протокол: bencode, handshake, peer wire, HTTP-трекеры |
| 9 | Обмен метаданными (`ut_metadata`) — работа magnet-ссылок без `.torrent` |
| 10 | Расширенный протокол (extension protocol), на котором работает `ut_metadata` |
| 15 | UDP-трекеры |
| 20 | Peer id в стиле Azureus (`-TR1000-` + 12 символов) |
| 23 | Компактные списки пиров в ответе трекера |

## Ограничения

Проект намеренно компактный. На данный момент **нет**:

- DHT, PEX и локального обнаружения пиров (LSD) — пиры берутся только с трекеров;
- шифрования трафика (MSE/PE) и uTP;
- web-seed и загрузки по HTTP (BEP 19);
- прокси и SOCKS;
- создания и редактирования `.torrent`, изменения списка трекеров;
- выборочной загрузки файлов внутри торрента (выбор кусков — только rarest-first по всему торренту);
- проверки уже скачанных файлов (recheck): при повторном добавлении торрент качается заново.

Кроме того:

- список торрентов не сохраняется между запусками — постоянными остаются только настройки (`settings.json`); после перезапуска торренты нужно добавить заново;
- кусок, который пир отдаёт битым, откладывается и запрашивается заново (пауза до 10 с по нарастающей) и не блокирует остальные куски; но если единственный недостающий кусок битый у всех пиров, торрент остаётся в состоянии загрузки — отдельного статуса «не скачивается» нет;
- интерфейс и установщики собраны и проверены только под Windows x64;
- ширина канала и число пиров ограничиваются настройками, глобального планировщика загрузок нет.
