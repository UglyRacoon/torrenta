# Torrenta

**Лёгкий торрент-клиент для Windows на Rust и Tauri.** Собственное ядро протокола BitTorrent, компактный интерфейс в одном окне и нативный `.exe` с установщиком — без Electron и без сторонних торрент-движков.

## О проекте

Torrenta — настольное приложение для Windows 10/11 x64, написанное целиком на Rust (бэкенд и торрент-движок) и TypeScript (интерфейс в WebView2). Движок живёт в отдельном крейте `torrent-core`, не зависит от Tauri и тестируется как обычная библиотека: разбор `.torrent` и magnet-ссылок, работа с HTTP(S)- и UDP-трекерами, peer wire protocol, хранилище кусков и планировщик загрузки.

В проекте нет готовых торрент-библиотек: bencode, метаданные, трекеры, обмен кусками и проверка SHA-1 реализованы в этом репозитории.

**Что не нужно:** Electron, внешний демон, аккаунт, телеметрия. Приложение работает локально и ничего никуда не отправляет, кроме announce-запросов на трекеры вашего торрента.

## Возможности

- **Добавление торрентов:** файл `.torrent`, magnet-ссылка, перетаскивание `.torrent` в окно, диалог выбора файлов.
- **Папка наблюдения:** если в настройках указана папка, приложение раз в несколько секунд проверяет её и само добавляет новые `.torrent`-файлы. Обработанный файл переносится в подпапку `done`, чтобы не добавляться повторно; недописанные файлы не читаются, пока не перестанут меняться.
- **Выборочная загрузка:** при добавлении открывается окно с составом торрента и папкой загрузки — ненужные файлы снимаются галочкой, по умолчанию выбраны все. Набор файлов можно поменять и после добавления, на вкладке «Файлы» в панели деталей: куски снятых файлов перестают запрашиваться, уже скачанное остаётся на диске.
- **Приоритеты файлов:** в панели деталей у каждого файла есть список «Высокий / Обычный / Низкий / Не скачивать». Куски с высоким приоритетом запрашиваются первыми, низкий уходит в конец очереди, «Не скачивать» исключает файл так же, как снятая галочка. Общий для двух файлов кусок получает максимальный из их приоритетов.
- **Перепроверка файлов:** пункт «Перепроверить файлы» в контекстном меню заново считает SHA-1 всех кусков с диска и восстанавливает прогресс по факту — пригодится после ручной правки или переноса скачанного. Пока идёт проверка, торрент показан состоянием «Проверка» с прогрессом.
- **Очередь и лимиты активности:** в настройках задаётся, сколько торрентов одновременно скачивать и сколько раздавать (0 — без ограничения). Лишние торренты ждут в очереди «В очереди» и включаются сами, когда освобождается слот; ручная пауза важнее очереди и слот не занимает.
- **Сессия:** список торрентов, их папки загрузки, выбранные файлы, приоритеты, паузы и лимиты сохраняются в `session.json` в каталоге конфигурации и восстанавливаются при следующем запуске. Копии `.torrent` лежат рядом, поэтому исходный файл можно удалить или переименовать. Настройка «Восстанавливать список торрентов при запуске» отключает и запись, и восстановление — для «чистого» старта.
- **Скачанные файлы не заняты:** пока торрент загружается, файлы открыты на запись, но при завершении, паузе или постановке в очередь приложение отпускает запись и оставляет файлы только для чтения. Поэтому скачанный `.exe` можно запускать сразу, не останавливая раздачу: Windows больше не отвечает «файл занят другой программой».
- **Magnet-ссылки:** получение метаданных у пиров по `ut_metadata` (BEP 9) без предварительного скачивания `.torrent`; список файлов для выбора показывается до добавления торрента.
- **Трекеры:** HTTP(S)-announce и UDP-announce (BEP 15), компактные списки пиров (BEP 23). В `left` объявления передаётся объём только выбранных файлов.
- **DHT (BEP 5):** собственный узел поверх UDP ищет пиров без трекера — полезно, когда трекер недоступен или его в торренте нет. Порт задаётся в настройках (`0` — любой свободный), узел один на приложение.
- **PEX (BEP 11):** пиры обмениваются известными адресами через `ut_pex`, поэтому рой собирается быстрее, даже если трекер отдал мало адресов.
- **Веб-сиды (BEP 19):** если в `.torrent` указан `url-list`, недостающие куски докачиваются по HTTP с зеркал — параллельно с пирами, с той же проверкой SHA-1, без повторной загрузки одного куска из двух источников.
- **Прокси:** SOCKS5 (с логином и паролем) и HTTP CONNECT для соединений с пирами, трекерами и веб-сидами. Адрес вида `socks5://user:pass@host:port` задаётся в настройках и применяется на лету.
- **Проброс порта:** UPnP-IGD и NAT-PMP сами открывают порт прослушивания на роутере, чтобы входящие подключения работали без ручной настройки.
- **Входящие подключения:** собственный TCP-приём на выбранном порту, не только исходящие соединения к пирам.
- **Скорость без скачков:** скорость в списке — средняя за ~8 секунд по реально пришедшим из сети байтам (включая веб-сиды), поэтому она не прыгает между «0 Б/с» и «8 МБ/с» на каждой проверке куска. Оценка «сколько осталось» считается по 30-секундному окну, обновляется раз в секунду и не перескакивает между «40 минут» и «3 часа»; при остановившейся загрузке показывается прочерк вместо выдуманного прогноза.
- **Размер роя на виду:** в строке списка рядом с нашими соединениями стоит размер роя по данным трекера — `пиры 27 (1 698)`, в карточке деталей — карточки «Сиды в рое» и «Личеры в рое». Это разница между «сколько сокетов у нас» и «сколько пиров в раздаче вообще», и она видна без открытия диагностики. Если трекер ещё не ответил, вместо числа честно написано «неизвестно».
- **Прогресс в реальном времени:** снимок состояния на каждые 500 мс — скорость загрузки и отдачи, число подключённых пиров, ETA, доля готовых кусков.
- **Раздача:** после завершения торрент продолжает отдавать куски (поведение настраивается). Раздачу можно ограничить: «Ограничение по ratio» (остановить, когда отдано/скачано достигнет N) и «Ограничение по времени раздачи, мин». Сработавший лимит паркует торрент — в списке видно «лимит раздачи · ×2,00», в деталях плашка с просьбой возобновить вручную; ручное «Продолжить» сбрасывает счётчик.
- **Управление:** пауза и продолжение для одного торрента или для всех сразу, удаление одним действием: в подтверждении галочка «Удалить скачанные файлы» — с ней данные стираются с диска, без неё торрент убирается только из списка.
- **Контекстное меню:** правый клик по торренту открывает меню в точке клика — пауза или продолжение, подробности, лимит скорости для этого торрента, «Перепроверить файлы», «Открыть папку торрента» (та папка, куда качается именно эта раздача) и удаление.
- **Лимиты скорости:** общий лимит в настройках и отдельный лимит для каждого торрента. Общий лимит делится между всеми загрузками, а не умножается на их число; `0` означает «без ограничения».
- **Автовыключение ПК:** переключатель в статус-баре. Когда все загрузки завершены, приложение взводит системный таймер на 60 секунд, показывает обратный отсчёт и позволяет его отменить.
- **Настройки:** каталог загрузки, лимиты скорости (КиБ/с), сколько торрентов одновременно скачивать и раздавать, порт прослушивания, максимум пиров на торрент, раздача после завершения, лимиты раздачи по ratio и времени, сеть (DHT, PEX, веб-сиды, проброс порта, порт DHT, прокси), расписание лимитов, последовательная загрузка новых торрентов, связывание файлов `.torrent`, автовыключение, тема оформления, запуск с Windows и поведение окна, папка наблюдения, уведомления о завершении и восстановление сессии — сохраняются в `settings.json` в каталоге конфигурации приложения.
- **Трей и автозагрузка:** значок Torrenta в области уведомлений Windows — левый клик открывает окно, меню значка даёт «Открыть Torrenta» и «Выход». Три опции в настройках: «Запускать при входе в Windows» (запись в ветку автозагрузки текущего пользователя), «Запускать свёрнутым в трей» и «При закрытии окна сворачивать в трей» — крестик тогда скрывает окно, а загрузки продолжаются; полностью закрыть приложение можно через «Выход» в меню значка. Подсказка значка показывает текущую скорость и число активных торрентов, не открывая окно.
- **Уведомления Windows:** когда загрузка завершается, а окно свёрнуто в трей или не в фокусе, приходит системное уведомление «Torrenta» с именем торрента. Пока окно на переднем плане, уведомление не отвлекает; переключатель есть в настройках.
- **Интеграция с системой:** открытие папки скачиваемого торрента в Проводнике (одним пунктом меню, без ручного поиска по каталогу загрузок), открытие внешних ссылок в браузере по умолчанию.
- **Один экземпляр:** повторный запуск `torrenta.exe` не открывает второе окно — уже работающее приложение поднимается и получает фокус, а второй процесс завершается. Так же ведёт себя двойной щелчок по `.torrent`, когда Torrenta уже запущена.
- **Открытие `.torrent` из Проводника:** двойной щелчок по файлу запускает Torrenta (или будит свёрнутую в трей) и сразу открывает обычное окно добавления торрента с предпросмотром состава.
- **Проверка и самолечение ассоциации:** при запуске (и по кнопке «Починить ассоциацию» в настройках) приложение смотрит, какая программа на самом деле открывает `.torrent`, и восстанавливает привязку, если она сломана или ведёт на удалённый/чужой exe. Живой чужой обработчик (например, qBittorrent) не перехватывается — вместо этого показывается честный статус «назначать не нужно, открывает другая программа». Именно эта проверка лечит последствия установки новой версии поверх старой, из-за которых двойной щелчок по торрент-файлу открывал приложение без окна добавления.
- **Выход из приложения:** кнопка «Выход» в футере сайдбара под «Настройками» завершает процесс полностью, даже когда включено «при закрытии окна сворачивать в трей».
- **Последовательная загрузка:** торрент можно качать по порядку кусков — от начала файла к концу, а не «где быстрее». Переключатель в опциях торрента, а значение по умолчанию для новых торрентов задаётся в настройках. Это не потоковое воспроизведение, а именно порядок загрузки.
- **Трекеры на виду:** вкладка «Трекеры» показывает текущий список, позволяет отредактировать его и применить без перезапуска торрента, а кнопка «Обновить трекеры» будит анонсер. Адреса проверяются по схеме (`http`, `https`, `udp`), дубликаты и мусор не сохраняются.
- **Расписание лимитов:** в настройках можно задать окно времени и отдельные лимиты загрузки и отдачи внутри него — например, днём без ограничения, ночью ограниченно. Окно может переходить через полночь.
- **Окно диагностики:** Ctrl+D (Ctrl+В в русской раскладке) открывает панель с состоянием движка: порт прослушивания, DHT и число узлов, PEX, веб-сиды, прокси, проброс порта, действующие лимиты, включённость расписания и последовательного режима, торренты, пиры, скорости и аптайм. Обновляется каждые 2 секунды.
- **Портативный режим:** если рядом с `torrenta.exe` лежит файл-маркер `torrenta-portable.txt` (или `portable`), настройки и сессия сохраняются в подкаталог `TorrentaData` рядом с программой — каталог можно перенести на флешку. Если писать рядом нельзя, приложение честно остаётся на обычном каталоге конфигурации.
- **Поиск и сортировка:** поиск по списку и сортировка по нескольким полям сразу (до трёх ключей) с запоминанием между запусками. Направление по умолчанию учитывает смысл поля: новые торренты и большие файлы — сверху, имена — по алфавиту.
- **Проверка обновлений:** команда и блок в окне диагностики. Сборка без ключа подписи честно сообщает, что автообновление не настроено, вместо «обновлений нет».
- **Собственное ядро:** один крейт без внешних торрент-зависимостей, покрытый юнит-тестами; тесты запускаются командой `cargo test --workspace`.

## Интерфейс

Одно окно в тёмной теме (есть светлая), четыре области:

| Область | Содержимое |
| --- | --- |
| Слева (сайдбар) | Фильтры по состоянию: все, загружаются, раздаются, завершённые, на паузе, ошибки |
| Сверху (панель) | Добавление magnet-ссылки или файла `.torrent`, поиск по списку, сортировка по нескольким ключам |
| В центре (список) | Строки торрентов: имя, прогресс, скорость загрузки и отдачи, наши пиры и размер роя в скобках, состояние |
| Справа (детали) | Метаданные выбранного торрента, вкладки «Файлы» (приоритет каждого файла, в том числе «Не скачивать»), «Трекеры», «Пиры» |
| Внизу (статусбар) | Скорость загрузки и отдачи, число активных торрентов, переключатель автовыключения и отсчёт до него |

Ширина сайдбара подстроена под содержимое и тянется мышью (или стрелками с клавиатуры) от полной подписи до полосы из одних иконок; выбранная ширина запоминается. Значок приложения и иконки пунктов стоят в одном столбце, а подписи меню выровнены по левому краю — сразу за иконками.

Если в выбранном фильтре нет ни одного торрента, список показывает не пустое место, а сообщение по центру области и кнопку «Сбросить фильтры» под ним — в верхней части, а не у нижней кромки окна.

Дополнительно: всплывающие уведомления (toasts), модальные окна настроек и добавления торрента, оверлей перетаскивания файлов, значок в области уведомлений Windows. Выпадающие списки, поля, переключатели и кнопки во всех окнах оформлены одинаково; цвет заголовка окна следует выбранной теме.

Палитра задана в [src/styles/tokens.css](src/styles/tokens.css) и проверяется скриптом `npm run check:contrast`: контраст текста к фону не ниже требований WCAG AA.

## Архитектура

Три слоя, каждый в своей части репозитория:

```
src/  ──invoke──▶  src-tauri/  ──прямые вызовы──▶  crates/torrent-core/
(WebView2 + TS)    (Tauri-команды, настройки,       (движок: метаданные,
                    состояние, события)              трекеры, пиры, куски, диск)
```

- **`crates/torrent-core`** — движок без Tauri. Модули: `bencode`, `metainfo`, `magnet`, `tracker`, `wire`, `bitfield`, `picker`, `selection`, `storage`, `peerid`, `dht` (BEP 5), `pex` (BEP 11), `web_seed` (BEP 19), `proxy` (SOCKS5 и HTTP CONNECT), `port_map` (UPnP-IGD, NAT-PMP), `engine` (`TorrentManager`, `Runtime` одного торрента, сессия с пиром, общие лимитеры сессии).
- **`src-tauri`** — тонкая обвязка: команды `get_state`, `preview_torrent`, `add_torrent`, `set_file_selection`, `recheck_torrent`, `set_file_priorities`, `set_torrent_limits`, `pick_torrent_files`, `pick_download_dir`, `pause_torrent`, `resume_torrent`, `pause_all`, `resume_all`, `remove_torrent`, `get_settings`, `set_settings`, `get_auto_shutdown`, `set_auto_shutdown`, `cancel_auto_shutdown`, `reveal_torrent`, `open_download_dir`, `open_external`, `quit_app`, `set_torrent_sequential`, `torrent_trackers`, `set_torrent_trackers`, `reannounce_torrent`, `engine_diagnostics`, `portable_info`, `association_status`, `repair_association`, `check_update`, `pick_watch_dir`, `take_open_request` — всего 34 команды. Состояние уходит в интерфейс событием `engine://state`, события движка — `engine://event`, обратный отсчёт автовыключения — `engine://auto-shutdown`, сигнал «открыть внешний источник» — `engine://open-source`. Модуль `single_instance.rs` держит единственный экземпляр и разбирает аргументы запуска (`.torrent`/magnet из Проводника), `association.rs` проверяет и при необходимости переписывает привязку расширения `.torrent` в реестре, `settings.rs` выбирает каталог данных (обычный или портативный).
- **`src`** — интерфейс на TypeScript без фреймворка: тонкий слой событий и отрисовка DOM. Тема применяется до первой отрисовки, чтобы не было мигания.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (слои, потоки данных, tokio-задачи, принятые решения) и [docs/CORE_API.md](docs/CORE_API.md) (публичный API ядра).

## Ограничения

Проект намеренно компактный. На данный момент **нет**:

- шифрования трафика (MSE/PE) и uTP;
- локального обнаружения пиров (LSD);
- создания и редактирования `.torrent` (список трекеров существующего торрента менять можно);
- автоматической ротации очереди по времени: слот отдаётся тому, кто раньше добавлен, и не переходит к следующему, пока предыдущий не завершится или не будет снят с паузы.

Кроме того:

- **DHT** делает до трёх раундов `get_peers` (с 1.8), но без полного итеративного обхода Kademlia; `announce_peer` отправляется без ожидания ответа; секрет для токенов не ротируется по времени; в таблицу узлов попадают только IPv4-адреса; нет BEP 42 (secure node id) и защиты от Sybil-атак. Сообщения `port` от пиров (BEP 5 relay) не обрабатываются;
- **PEX** работает только по IPv4: `added6`/`dropped6` не формируются, входящие IPv6-поля игнорируются; в поле до 200 адресов (с 1.8; было 50), длинный список обрезается, а не отбрасывается;
- **прокси** покрывает только TCP (CONNECT): DHT и UDP-трекеры идут напрямую, минуя прокси, — при выборе прокси ради анонимности это надо учитывать. SOCKS5 подключается по IP-литералам (имя домена по ATYP 0x03 не отправляется), `socks5h://` ведёт себя как `socks5`; HTTP-прокси поддерживает только Basic-авторизацию, `407` считается отказом. Схема `https://` в поле настроек после сохранения показывается как `http://`;
- **проброс порта** — best effort: пробуется UPnP-IGD, затем NAT-PMP; внешний порт не подбирается (просим равный порту прослушивания), IPv6 и PCP не поддерживаются, шлюз NAT-PMP определяется эвристикой `x.y.z.1`, а ошибки молча игнорируются — отдельных событий и индикатора в интерфейсе нет. Живой прогон требует роутера с UPnP/NAT-PMP и в автотестах помечен `#[ignore]`;
- **шифрование трафика (MSE/PE) не реализовано**: пиры, которые требуют шифрование, недостижимы — это главное оставшееся отличие от qBittorrent; uTP (BEP 29) тоже нет, обмен только по TCP;
- **скорость в интерфейсе — средняя за ~8 секунд**, поэтому при резком старте или остановке загрузки цифра догоняет реальность несколько секунд; так сделано специально, чтобы не было скачков. Окно запросов к пиру подстраивается эвристикой (8..512 блоков), а не точной оценкой полосы и задержки;
- **размер роя** известен только после ответа трекера: у раздачи без трекеров (только DHT и PEX) счётчики сидов и личеров остаются «неизвестно»;
- **веб-сиды** управляются одним переключателем: таймауты (10 с на соединение, 30 с на чтение) и 4 параллельных запроса — константы модуля, не настройки; если сервер не поддерживает `Range`, кусок вычитывается последовательным пропуском байтов, что медленно;
- **лимиты раздачи** проверяются тикером (500 мс), поэтому остановка может отставать от порога на один тик; время раздачи не идёт на паузе; сработавший лимит требует ручного «Продолжить» — автопродолжения по расписанию нет;
- список торрентов сохраняется в `session.json`, но magnet-торренты восстанавливаются по ссылке: до получения метаданных имя и размер не известны, а приоритеты «Низкий»/«Высокий» у них не возвращаются; если записанная папка загрузки больше не существует, используется каталог загрузки по умолчанию;
- уведомление о завершении показывается один раз на торрент и не настраивается по типам: звук и оформление задаёт Windows, а при выключенных системных уведомлениях оно не появится;
- папка наблюдения просматривает только верхний уровень и не обходит подкаталоги; файл, который не удалось добавить, всё равно переносится в `done`, чтобы ошибка не повторялась каждый тик, — причина при этом пишется только в журнал;
- подсказка значка обновляется не чаще раза в 2 секунды и обрезается по длине, поэтому скорость в ней может слегка отставать от статусбара;
- при выборочной загрузке прогресс, ETA и `left` у трекера считаются по выбранным файлам: торрент может быть «завершён», занимая на диске меньше полного размера, а счётчик готовых кусков при этом меньше 100%;
- снятие файлов с загрузки не удаляет уже скачанные данные — они остаются на диске до удаления торрента с файлами;
- кусок, который пир отдаёт битым, откладывается и запрашивается заново (пауза до 10 с по нарастающей) и не блокирует остальные куски; но если единственный недостающий кусок битый у всех пиров, торрент остаётся в состоянии загрузки — отдельного статуса «не скачивается» нет;
- интерфейс и установщики собраны и проверены только под Windows x64;
- автозагрузка работает через ветку реестра текущего пользователя (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) и не требует прав администратора; при переносе `.exe` в другое место путь обновляется при следующем запуске с включённой опцией;
- значок в трее создаётся всегда, но сворачивание по крестику включается только опцией в настройках: при выключенной опции крестик закрывает приложение, как раньше;
- скорость ограничивается общим лимитом сессии (делится между торрентами) и отдельным лимитом торрента; сколько торрентов качать и раздавать одновременно, задаётся в настройках (0 — без ограничения, значения больше 100 приводятся к 100);
- перепроверка проверяет только то, что лежит на диске: пока она идёт, обмен с пирами остановлен, а после неё торрент продолжает работу с уже известными пирами — новых адресов проверка не ищет;
- состояние «Проверка» видно в фильтре «Все» со значком «Проверка», но не попадает в «Загрузки» и не занимает слот активной загрузки: ограничение одновременных загрузок его не учитывает;
- на паузе и в очереди файлы торрента открыты только для чтения, поэтому запуск скачанного `.exe` работает, а запись в эти файлы другими программами до завершения раздачи — нет; при активной загрузке файл по-прежнему открыт на запись;
- ассоциацию `.torrent` регистрирует установщик (NSIS — ключами `HKCU\Software\Classes` для текущего пользователя, без прав администратора; MSI — рекламируемыми ключами WiX), а при запуске приложение проверяет фактический обработчик и восстанавливает привязку, если она ведёт на несуществующий или чужой exe. Ключи `UserChoice`/`UserChoiceLatest` и их `Hash` приложение не подделывает: битый выбор оно удаляет, а живой чужой обработчик (например, qBittorrent) не отбирает — в этом случае в настройках честно написано, что открывает другая программа, и привязку надо менять через «Параметры → Приложения → Приложения по умолчанию»;
- последовательная загрузка — это порядок кусков, а не потоковое воспроизведение: плеер не подключается, приоритеты файлов в этом режиме не действуют, и если нужный по порядку кусок есть не у всех пиров, скорость может просесть;
- в редакторе трекеров адреса проверяются по схеме и наличию хоста, дубликаты отбрасываются, а всё сверх 100 адресов молча не сохраняется; «Обновить трекеры» только будит анонсер, поэтому результат Announce кнопка не показывает;
- расписание лимитов меняет лимиты, но не ставит торренты на паузу; местное время берётся через Win32 `GetLocalTime`, а вне Windows (где расписание используется только в тестах) — по UTC; дни недели и часовой пояс не учитываются;
- окно диагностики только читает состояние; поле проброса внешнего адреса берётся без ожидания замка и может показать «нет данных», а `dht_port` — это настроенное значение, а не фактически занятый UDP-порт;
- портативный режим меняет только каталог данных (маркер рядом с `torrenta.exe` → подкаталог `TorrentaData`); установка и обновление программы всё равно идут в обычное место, а при отсутствии прав на запись рядом с exe приложение тихо остаётся на обычном каталоге конфигурации;
- автообновление не включено: в релизе нет ключа подписи и адреса фида, поэтому проверка обновлений честно возвращает «обновления не настроены», а не «обновлений нет»;
- привязка `magnet`-ссылок регистрируется только как ProgId, а не как URL-протокол: открытие `magnet:` из браузера этой версией не обещается;
- второй запуск приложения не создаёт второе окно: аргументы передаются работающему экземпляру, а второй процесс завершается; если Torrenta не была ассоциирована с `.torrent`, двойной щелчок по файлу запустит её без источника — файл откроется после выбора Torrenta в «Открыть с помощью»;
- «Выход» в сайдбаре и в меню значка трея завершает процесс всегда, независимо от настройки «при закрытии окна сворачивать в трей»; эта настройка влияет только на крестик окна.
